# Documentation–code consistency (problem taxonomy)

This note names the **16 problem categories** used when designing the documentation–code consistency review ([US-036](../../backlog/user-stories/US-036-documentation-code-consistency-review.md)). The detailed table, MVP phases, and workflow live in that user story.

**Outputs**: Run `./scripts/doc-code-review.sh` and read the latest report under `project-management/reports/` (e.g. `doc-code-consistency-latest.md`).

**Categories (summary)**:

1. Explicit contradictions (counts, parameters, behavior)  
2. Inconsistencies (terminology, conflicting docs)  
3. Stale documentation  
4. Incomplete docs  
5. Defaults and implicit behavior  
6. Error handling  
7. Performance  
8. Dependencies  
9. API changes  
10. Workflows  
11. Configuration  
12. Data types  
13. Security  
14. Logging and diagnostics  
15. Backwards compatibility  
16. Examples  

For full definitions and automation priorities, see **US-036**.
